### 2.1 跨出 3 天窗口的行程

请求：上海 → 成都，2026-11-20 至 2026-11-22（原句“11月20日从上海去成都玩3天，2个人，人均3000，喜欢美食和博物馆，节奏轻松，必去宽窄巷子，不去酒吧”）。

| 日期 | 天气 | 温度 | 来源 |
| --- | --- | --- | --- |
| 11-20 | 多云 | 7~13℃ | `qweather_forecast` |
| 11-21 | 阵雨 | 6~13℃ | `qweather_forecast` |
| 11-22 | 晴 | 6~13℃ | `qweather_forecast` |

说明：

- 该行程终点距今 18 天，服务按终点跨度自动选择 `/v7/weather/30d`，不再因超出 3 天窗口而回退历史气候；
- 跨度规则：≤3 天用 `3d`，≤7 天用 `7d`，≤10 天用 `10d`，≤15 天用 `15d`，≤30 天用 `30d`；
- 只有起点距今 ≥30 天时才回退历史气候参考，并在结果中标注来源为 `climate_reference`；
- 天气请求使用本地城市坐标表，不依赖 GeoAPI，避免凭据的 API 限制导致城市搜索被拒。

说明：

### 3.1 长沙行程数据真实性复核

原句：“2026-12-01至2026-12-04去长沙，3人，总预算9000”（补充出发地“上海”后生成，2026-11-05 实测快照）。

| 指标 | 结果 |
| --- | --- |
| 地点来源 | `amap_live` |
| 住宿 | 高德返回参考最低价的酒店，3 晚 × 2 间，单间参考价 115 元/晚（`biz_ext.lowest_price`） |
| 餐饮 | 单餐人均 16–278 元不等，均来自高德 `biz_ext.cost` |
| 门票 | 高德未提供，标注“未获取，0 元不代表免费” |
| 预算完整度 | `partial`，仅汇总已获取价格 |
| 概述 | 仅列出已安排地点，不含预约、限流、票价等外部结论 |

复核前曾出现的问题与修复：

- 旧实现忽略 `biz_ext`，把餐饮均价和房价写成 0，预算看起来像编造；
- 旧实现把缺失营业时间写成 `00:00-23:59`，并把 0 元当作真实价格；
- 大模型曾被用于生成“每日限流、提前官网预约”等提示，现已删除该能力，仅保留禁词校验后的概述。

## 5. 已知限制

- 本次验证覆盖未来 3 天内、18 天与 26 天三种跨度，未逐日验证 4–15 天与 19–30 天；
- 高德的价格与营业时间依赖 POI 的 `biz_ext` 字段，不同商户返回完整度不一致；缺失时会明确标注未获取；
- 未验证高德实时路况或驾车路线；
- 未验证和风预警、空气质量等未使用的接口；
- 真实 Key 的额度、限流与欠费状态由外部平台决定，应用只做失败回退并保留数据来源标注。

## 6. 复现方式

1. 在项目根目录 `.env` 配置：

   ```ini
   AMAP_API_KEY=...
   QWEATHER_API_KEY=...
   QWEATHER_API_HOST=https://<你的 API Host>
   ```

2. 启动服务：

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765
   ```

3. 检查 Provider：

   ```powershell
   Invoke-RestMethod http://127.0.0.1:8765/api/health | ConvertTo-Json
   ```

4. 页面中选择未来 30 天内的日期：成都用于验证天气，青岛用于验证地图。天气场景保持“自动”。
